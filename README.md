# Trust Is the Attack Surface

> **供應鏈攻擊不是攻破你的密碼學或漏洞,而是攻破「信任的轉移鏈」。**
> *They don't break your crypto — they break your trust.*

一份關於**軟體供應鏈攻擊**的客觀調查:標誌性案例的事實重建、攻擊全貌與分類、以及橫跨「安裝前 / 安裝時 / 安裝後」的防禦現況與開放問題。**重一手來源、重時間戳、明確區分「已證實 / 推測 / 未證實」。**

---

## 為什麼做這份

供應鏈攻擊的可怕之處在於:你什麼都沒做錯——你用了正版、簽章過、來自官方來源的東西——但你信任的上游被下了毒,毒順著「鏈」流進你的系統。攻擊者只需在「我信任 X、X 信任 Y」的某一環插入自己,整條鏈的簽章、HTTPS、registry 完整性反而幫他把惡意產物「可信地」分發出去。

最有力的一個事實:2025 年的 **Shai-Hulud** npm 蠕蟲,惡意版本**全帶有效的 SLSA Build Level 3 provenance 簽章**——證明完整性防線(簽章 / SBOM / provenance / 2FA)可以**全數通過,套件仍然是毒的**。這就是本調查的核心命題:現有防禦多在防「**完整性**(東西沒被竄改)」,但攻擊攻的是「**真實性**(合法的人/管道本身就是惡意)」。

## 三句話帶走

1. **攻擊本質**:漏洞利用攻「弱點」;供應鏈攻擊攻「信任」——後者更難防,因為防線本身(自動更新、官方 registry、CI)就是傳播管道。
2. **最危險的盲區**:「**合法但惡意**」——當惡意由被信任的合法主體、經合法管道、以合法形式發出時,完整性控制全數通過卻無法阻擋。
3. **防治規律**:成本與可靠性沿安裝生命週期單調惡化——「安裝前」最便宜且可阻斷,「安裝後」最貴且無法保證除淨。一旦執行,對手是「一整套互為備份、扎根系統各角落的惡意生態」。
